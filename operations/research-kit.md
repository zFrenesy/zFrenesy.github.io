# Research repository kit

The research repository carries the trusted agent and intake files (ADR 0012, spec §20). They are rendered from `rp/contribute/kit/templates/` in this repository, bound to one platform commit, and committed to `research:main`:

| File | Purpose |
| --- | --- |
| `AGENTS.md`, `CLAUDE.md`, `.gemini/settings.json` | Instructions for coding agents, including legacy prompts A–D adapted as initial research, final self-audit and problem proposal |
| `CONTRIBUTING.md` | The four routes and the five rules from §18 |
| `.devcontainer/devcontainer.json` | Codespaces image and `gh` feature pinned by digest; installs `rp` at the pinned commit with hash-locked dependencies |
| `.github/ISSUE_TEMPLATE/*.yml` | Issue forms. Field ids `problem`, `contribution` and `parent` receive the website's prefill |
| `.github/PULL_REQUEST_TEMPLATE.md` | Pull request checklist |
| `.github/workflows/check.yml` | Thin caller of this repository's `research-check.yml` at the same pinned commit |

`browse/aliases.json` and `browse/README.md` are generated by the importer (and later by managed publication). They are not part of the kit.

## Update the pin

1. Push the platform commit to `we-solve-staging/we-solve-staging.github.io:main`. It must contain `.github/workflows/research-check.yml`.
2. Render the kit into a clean checkout of `research:main` (outside Google Drive):

   ```sh
   python -m rp.contribute.kit --out <checkout> --research we-solve-staging/research \
     --platform we-solve-staging/we-solve-staging.github.io --ref <platform-sha> \
     --site https://we-solve-staging.github.io/
   ```

3. Review `git diff`, commit with a general message (`Update research`), and push to `research:main`.
4. Create the intake labels once:

   ```sh
   for label in intake attempt review problem; do gh label create "$label" --repo we-solve-staging/research --force; done
   ```

5. Run `pages.yml` with the new `research_sha` if `browse/` changed, and update `STAGING_RESEARCH_SHA`.

## Checks and limits

- `research-check.yml` runs on `pull_request` with a read-only token and no secrets. It checks out the merge result with credentials disabled, installs the platform's hash-locked dependencies, and runs `rp check --base HEAD^1 --head HEAD` from the pinned platform commit with `python -P`. No contributor code runs.
- The org's Actions policy allows reusable workflows from repositories in the same organisation. The SHA-pinning requirement applies to the `uses:` line, which the kit pins.
- The check is **advisory**. A pull request can change its own caller, and first-time contributors' fork runs wait for approval, so no required path depends on it. The milestone 4 gate adds a trusted required check.
- Pull requests and issues queue; nothing is merged by hand.
